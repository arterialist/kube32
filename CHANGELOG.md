## [Unreleased]

### Added

- JSON Patch (`application/json-patch+json`, RFC 6902) on every resource that accepts a patch, so `kubectl patch --type json`, Helm, Argo CD and k9s work ([docs/api-reference.md](docs/api-reference.md)). The operations are `add`, `remove`, `replace`, `move`, `copy` and `test` at JSON Pointer paths, with `~0` and `~1` escapes and `-` to append to an array. A patch applies whole or not at all, and a failing operation answers `422 Invalid`. The Deployment `scale` subresource takes JSON patches against the `Scale` object.

- The `wordsketch` example ([apps/wordsketch](apps/wordsketch/README.md), `examples/wordsketch.yaml`) turns a word spoken to the Cardputer into a doodle and a short story. A pod on the Cardputer listens with a keyword spotter (cat, dog, bird, house, tree, bed; integer front end, weights read in place from a blob) in 79 KiB of its pod pool, an entry-point pod on a board with PSRAM draws the word with a class-conditional diffusion model and publishes every step's image, stories260K writes the story, and the Cardputer's screen shows both as they form. The models, their training code and their C inference, which computes the reference's bits, are in `models/`.
- `k32_attention_full_f32_i8` ([docs/app-development.md](docs/app-development.md#linear-algebra)): the attention of several query positions that each see the whole window, every head in one call, the bits of the three calls per head. The int8 and int4 products on the ESP32-S3 hold a chunk of 64 weights in vector registers for every vector of a `k32_matmul_*` call and store a row block's results vector by vector.
- `k32_attention_f32_i8` ([docs/app-development.md](docs/app-development.md#linear-algebra)): the attention of several query positions over an int8 KV cache, every head in one call, the bits of `k32_matvec_f32_i8`, `k32_softmax_f32` and `k32_vecmat_f32_i8` per head. `llm-speculative` and `llm-pipeline` attend with it: one call per layer for all positions of a pass instead of three per head and position.
- `k32_conv3x3_i8` ([docs/app-development.md](docs/app-development.md#linear-algebra)): a 3x3 convolution with padding 1 over several int8 maps in one call, with stride 1 or 2 and the input read as its 2x nearest-neighbour upsample, the weights read once per call in cache-sized blocks and the products on the vector instructions of the ESP32-S3; the bits of `k32_matvec_i8` over each pixel's patch. `k32_add_f32_i8` adds a scaled int8 map to floats, and `k32_quantize_i8_static` quantizes at a fixed scale. The doodle model of `wordsketch` draws with them: one call per chunk of output rows for both conditions of a guided step, and the step and class bias, the skip, SiLU and the next input's quantization as element-wise calls per row.
- `k32_fft_q15` ([docs/app-development.md](docs/app-development.md#linear-algebra)): the butterflies of an integer radix-2 FFT with Q15 twiddles, natively, for audio front ends. `n` from 2 to 4096 (a power of two); `K32_ERR_INVAL` otherwise. A 512-point frame of the keyword spotter's front end drops from 127,000 interpreter operations to 30,000 with the same bits.
- `kube32-sim --sim-mic <file>` plays a recording to `k32_mic_read` in real time ([docs/cli-reference.md](docs/cli-reference.md)).
- `kube32-sim` workers follow the network ([docs/cli-reference.md](docs/cli-reference.md#following-the-network)). `--node-ip auto`, the default for a worker whose API server is on another host, reports the local address that the system uses to reach the API server and patches the Node's `InternalIP` when the network changes. A control plane started with `--node-ip` announces its API address in HELLO frames, and a worker that has had no answer from its API server for 30 seconds dials the announced address in place, without restarting its pods, as boards do. A worker that dials another host also sends its HELLO to the UDP broadcast address on port 7400, so that a control plane that has lost track of it answers with its API address.

- Blobs ([docs/storage.md](docs/storage.md#blobs)): named, read-only data such as model weights, which pods read in place instead of loading it into their memory. A node keeps them in a flash region mapped into the address space (a `blobs` data partition, or the passive app slot between firmware updates) and in `kube32/blobs/` on its microSD card; `kube32-sim` keeps the region in a file. Pods open the blobs named in `kube32.io/blobs` with `k32_blob_open`, `k32_blob_size`, `k32_blob_read`, `k32_blob_mapped` and `k32_blob_close`, and the linear algebra imports read weights and scales from a mapped blob through `K32_BLOB_ADDR`. The kubelet endpoint serves `/blobs` through the node proxy. `apps/blobbench` measures a node's blob throughput and, at `/check`, compares the linear algebra imports with a pod's own loops, and `K32_CMD:BLOBS` lists the stores.
- Cardputer audio ([docs/peripherals.md](docs/peripherals.md#speaker-and-microphone)): `k32_audio_play` plays 16-bit PCM, `k32_mic_read` records 16 kHz PCM from the PDM microphone (`hardware.kube32.io/microphone`) with its DC offset removed and a gain of 16, and the speaker never plays louder than a quarter of full scale. The two share a clock pin and take turns, the speaker first. `K32_CMD:MIC:<ms>` prints the microphone's levels, `K32_CMD:MICGAIN:<n>` sets its gain and `K32_CMD:SDKHZ:<khz>` sets the microSD card's SPI clock.
- `K32_CMD:HEAPMIN` reports the internal heap's lowest free size over an interval, and `[MEM]` lines name the task of a failed allocation. Firmware built with `CONFIG_HEAP_USE_HOOKS` adds `K32_CMD:HEAPWATCH`, each task's internal allocations at the heap's low point ([docs/flashing-troubleshooting.md](docs/flashing-troubleshooting.md#diagnostics)).
- Native linear algebra for pods ([docs/app-development.md](docs/app-development.md#linear-algebra)): `k32_matvec_i8` and `k32_matvec_i4` multiply int8 or int4 matrices with per-row scales by an int8 vector, `k32_matvec_f32_i8` and `k32_vecmat_f32_i8` compute attention over an int8 KV cache, and `k32_softmax_f32` normalizes scores. `k32_matmul_i8` and `k32_matmul_i4` apply one matrix to several vectors and read each row once for all of them. `k32_rmsnorm_f32`, `k32_quantize_i8`, `k32_rope_f32`, `k32_swiglu_f32`, `k32_add_f32` and `k32_argmax_f32` run the element-wise steps of a transformer over many vectors in one call. On the ESP32-S3 the integer products run on the core's vector instructions (PIE). The node checks every operand against the pod's linear memory, an operand outside it traps with a message that names it, and a metered pod pays for the work from its execution budget. The results are the same bits on every node; `k32_expf` in `k32_app_abi.h` is the exp the softmax uses. The Rust SDK wraps them in the `linalg` feature, and `kube32 check` knows them. `llm-pipeline` computes its matrix products, attention and element-wise steps with them.
- `models/` ([docs/examples/models.md](docs/examples/models.md)): four small networks with their training code, test vectors and C inference for pods. A target language model for speculative decoding, a masked diffusion language model, a Quick, Draw! doodle denoiser in two sizes, and a Speech Commands keyword spotter trained for far-field speech with room acoustics, noise and other voices. Each model's numpy reference (`models/common/k32ref.py`) computes the bits a pod computes, `make -C models check` compares the C inference with the test vectors on the host, and `models/playground.py` runs the models on the host with a web page. `apps/llm-pipeline/tools/spec.py` runs speculative decoding as the reference and writes the speculative pod's blobs, and `models/kws/farfield.py` scores a keyword spotter on far-field, false-trigger and synthesized-voice tests.
- The `llm-speculative` example ([apps/llm-speculative](apps/llm-speculative/README.md), `examples/llm-speculative.yaml`) runs greedy speculative decoding in one pod on the control plane: a 3.6 M-parameter model trained with stories260K's tokenizer reads its int4 weights in place from the node's flash blobs, stories260K drafts k tokens from its own blob, and one pass of `k32_matmul_i4` checks them all. Its HTTP API runs a prompt with the target alone, with drafts or with the draft alone, and reports tokens/s, acceptance, the time of each pass and the bytes read from flash. `tools/spec.py bench` checks every run against the reference, token for token and pass for pass.
- The `llm-diffusion` example ([apps/llm-diffusion](apps/llm-diffusion/README.md), `examples/llm-diffusion.yaml`) runs a masked diffusion language model: the weights stay in a flash blob and `k32_matmul_i8` reads them in place, and a request returns the window's text after every step with the time it took.
- The `llm-pipeline` example ([apps/llm-pipeline](apps/llm-pipeline/README.md), `examples/llm-pipeline.yaml`) runs the stories260K language model as three pipeline stages: the embedding and layers 0-2 on the control plane, layer 3 in int4 in the Cardputer's 80 KiB pod pool, which shows the text on its screen, and layer 4 with the classifier on the fastest node, a `kube32-sim` worker. A coordinator pod runs greedy generations with an HTTP API and Server-Sent Events and reports per-stage compute and hop times. `tools/llm.py` quantizes and splits llama2.c models and computes the reference tokens, which the pipeline matches bit for bit. A shard given `MODEL_BLOB` reads its slice in place from a blob. The integration suite `llm` runs it on three simulator nodes, including a move of the last stage with its KV cache while it generates.
- The `kube32` command, a Python package on PyPI installed with `uv tool install kube32` or run with `uvx kube32` ([docs/install.md](docs/install.md)). It runs every `kube32-cli` command, under both names, and the serial gateway as `kube32 gateway`. New commands: `kube32 new` creates a C project (Makefile, request pod, the ABI header) or a Rust crate (the counter example, `kube32-sdk` of the same release); `kube32 flash` writes the release firmware, checked against its SHA-256, with esptool; `kube32 console` opens a board's serial console; `kube32 sim` runs `kube32-sim` from `PATH`, from the release tarball, or from the container image with `--docker`; `kube32 version` prints the package's and the cluster's versions. `kube32 build` builds the current directory when given none. The package version is the release tag, and each GitHub release publishes the package to PyPI. `tools/kube32-cli` and `tools/kube32_serial_gateway.py` run the package from a checkout.
- `kube32 mcp`, a Model Context Protocol server for AI agents such as Claude Code (`claude mcp add kube32 -- uvx kube32 mcp`), on stdio or streamable HTTP, with no dependency beyond the Python standard library ([docs/mcp.md](docs/mcp.md)). Tools list nodes and Devices, read a Device (starting an Idle driver, and sampling it over time), describe it in a reference document, send it actions, and build, deploy, inspect and delete pods bound to a Device. The annotations `kube32.io/notes` and `kube32.io/limits` describe a Device and its safe limits; the server refuses actions outside the limits, failing closed on a rule it cannot read, and records each action as an Event on the Device. Writes need `--allow-writes` and deploys `--allow-deploy`; deployed pods reach hardware only through drivers. Resources serve each Device's reference, the pod ABI header and a guide to writing Device pods, and the prompt `explore-then-codify` walks an agent from reading a part to deploying code for it.
- `kube32 build` exports `__heap_base` from C modules: the end of the static data and the stack, from which `kube32 mcp` sizes a pod's memory.
- Releases ([docs/releases.md](docs/releases.md)). A tag `vX.Y.Z` runs `.github/workflows/release.yml`, which publishes the GitHub Release with the firmware (a merged image for first installs, the bootloader, partition table, `otadata` and app as separate parts with `flash.json`, and an ESP Web Tools manifest), `kube32-sim` for macOS (arm64, x86_64) and Linux (x86_64, arm64, statically linked), the C SDK archive and SHA-256 checksums; the container image `ghcr.io/arterialist/kube32-sim` for `linux/amd64` and `linux/arm64`; and the `kube32-sdk` crate. A manual run with dry-run builds everything without publishing.
- Browser installer ([docs/flash.md](docs/flash.md)): ESP Web Tools on the docs site writes the latest release to a board over Web Serial and sets up its Wi-Fi.
- Improv Wi-Fi serial on the firmware console: an installer asks for the node's state, information and the networks in range, and sends Wi-Fi credentials. The node joins the network, answers with the API server URL, stores the credentials and restarts on that network.
- `GET /version` reports the kube32 release as `kube32Version`, and `kube32-sim --version` prints it.
- A `Dockerfile` for `kube32-sim`, and the C SDK template in `sdk/c`.
- Pod migration ([docs/migration.md](docs/migration.md)). The Checkpoint controller carries out `kube32.io/v1` Checkpoints: `Save` stores a running pod's state, `Move` replaces the pod on another node, where it restores with the same name and owners. A Deployment counts one pod throughout. A failed restore puts the pod back on its source node from the same checkpoint. Blockers (hardware grants, node storage volumes, entry points, open files, `kube32.io/migration: Never`) are refused and named.
- `POST /api/v1/namespaces/<ns>/pods/<name>/eviction` (`policy/v1` Eviction): `kubectl drain` moves the pods that can move and deletes the others. `kubectl cordon` and `uncordon` work as in Kubernetes.
- Migration policies in the `kube32.io/migration` annotation: `OnDrain` (default), `Never` and `Auto`, which moves pods off nodes under memory pressure and, with `kube32.io/placement: fastest`, to nodes at least twice as fast by `kube32.io/interp-mops`. `kube32.io/checkpoint-interval` saves a pod periodically, and a pod on a lost node restores on another node from its latest periodic checkpoint.
- `kube32-cli checkpoint`, `move` and `checkpoints`.

- `bench_ops` (`tools/bench_ops.cpp`) counts the wasm3 operations that each bench kernel executes, with the interpreter built as the boards build it. [docs/benchmarks.md](docs/benchmarks.md) uses the counts to explain why the ratio to native code changes from kernel to kernel.
- `K32_CMD:BENCH` runs benchmark kernels natively on a node's console. The bench pod (`apps/bench`, `images/sd/bench.wasm`) runs the same kernels in the sandbox. [docs/benchmarks.md](docs/benchmarks.md) lists the measurements.
- Kubernetes API server on port 6443 serving Pod, Node, Namespace, Service, Endpoints, EndpointSlice, ConfigMap, Secret, Event, Deployment, DaemonSet, Job, Lease, Ingress, NetworkPolicy, NodeMetrics, PodMetrics, and subject access reviews.
- Pod egress: `k32_http_call` reaches HTTP hosts outside the cluster by IPv4 address or DNS name, resolving Service names as Kubernetes DNS does; NetworkPolicy egress rules (`ipBlock` with `except`, pod and namespace selectors, numbered, named and ranged ports) restrict Service and outside calls on the calling node; the control plane routes its cluster access point to its station uplink with NAT and offers the uplink's name server.
- HTTPS for pod egress: `k32_http_call` reaches `https://` hosts and verifies their certificates against the ESP-IDF common CA bundle, including validity dates once SNTP has set the clock. The control plane makes the TLS connections on up to two sessions in PSRAM, directly for its own pods and through the egress gateway (`POST /apis/kube32.io/v1/egress`) for pods on workers. The gateway accepts nodes by the cluster bearer token, or by node address when the cluster has none, and applies the calling pod's NetworkPolicies. New error codes: `K32_ERR_CERT` (`-129`), `K32_ERR_TLS` (`-71`), and `K32_ERR_BUSY` (`-16`). `k32_http_status` returns the status of an answer whose body did not fit the buffer, and `kube32-sim --egress-ca` adds trusted roots.
- `k32_unix_time_ms` gives pods the node's wall clock, or `0` while it is not set.
- The `webhook` example forwards channel events, such as `rfid.tag` and `ir.received`, to an HTTPS endpoint as JSON. It reads its URL from a Secret, retries from a bounded queue with back-off, and ships with a NetworkPolicy that allows only TCP port 443.
- Watch streams with bookmarks and `sendInitialEvents`, Table output, OpenAPI v3 index, `fieldValidation=Strict`, `dryRun=All`, pagination, merge and strategic-merge patches, and protobuf request bodies for ConfigMap, Secret, Namespace, Service, Deployment, and Job.
- Pod scheduler filtering by node state, `nodeName`, `nodeSelector`, memory, `esp32.io/psram`, and peripheral counts (`esp32.io/gpio`, `esp32.io/i2c`, `esp32.io/adc`, `esp32.io/uart`).
- Deployment, DaemonSet, and Job controllers, plus node Lease tracking with automatic tainting and pod eviction.
- wasm3 container runtime supporting request pods (`k32_alloc`, `k32_handle`, `k32_init`, `k32_tick`, `k32_event`), static asset serving with gzip negotiation (`k32_resp_asset`), and entry-point pods (`_start`, `app_main`, `main`).
- Per-pod linear memory limits across internal RAM and PSRAM (including sub-page limits below 64 KiB), configurable wasm3 value stacks (`kube32.io/wasm-stack`) and gas execution budgets (`kube32.io/execution-budget`), pool-first allocation on boards without PSRAM, one shared interpreter stack for all pod calls, trap-specific exit codes, and `Always`, `OnFailure`, and `Never` restart policies with exponential back-off.
- Pod environment variable injection from ConfigMaps, Secrets, `fieldRef`, and service links, with `$(VAR)` expansion.
- Kubelet memory admission: a pod that does not fit yet waits `Pending` with reason `InsufficientMemory`, and one larger than the node can hold fails with `OutOfmemory`, each with an Event. Pod allocations never take the system reserve of the internal heap (24 KiB on boards without PSRAM).
- Port 80 Ingress controller with host and path matching, Service backend routing across nodes, `StaticBundle` asset serving, and Server-Sent Events streaming (`kube32.io/event-stream`).
- Inter-pod event pub/sub (`k32_event_emit`, `kube32.io/event-topics`) over ESP-NOW and UDP port 7400, plus synchronous pod-to-pod HTTP calls (`k32_http_call`) gated by the `SERVICE_CALL` capability.
- Single firmware image with automatic control-plane and worker role detection from PSRAM presence, configurable over the serial console (`K32_CMD:*`) and persisted in NVS.
- Log-structured, CRC-checked object store journal on a raw flash partition or microSD card with pre-write capacity checks, object-store-full errors, and API writes committed before the response, persistent volume claims via the `k32_fs_*` ABI, rotated container logs, and network storage access (`GET`, `PUT`, `DELETE`) via the node proxy subresource (`/api/v1/nodes/<node>/proxy/storage/<path>`).
- Optional bearer token authentication (`K32_CMD:TOKEN`) and self-signed ECDSA P-256 TLS (`K32_CMD:CERT`) with HTTP/1.1 keep-alive multiplexed with plain HTTP on port 6443.
- Capability firewall and `generic` and `cardputer` board profiles governing GPIO, ADC, I2C, UART, display, keypad, speaker, IPC, and microSD resources.
- Rust guest SDK (`sdk/rust`), `tools/kube32-cli` (`build`, `check`, `deploy`, `embed`, `sd-push`, and recursive file/directory `push`), USB serial HTTP gateway with concurrent streamed requests (`tools/kube32_serial_gateway.py`), flashing script (`scripts/flash.sh`), and host simulator (`kube32-sim`, supporting `--psram 0` for boards without PSRAM, `--tls`, and `--help`).
- Example workloads and manifests including the four-pod Tessera issue tracker (`apps/tessera`), `echo`, and `i2cscan`.
- Infrared for pods: RMT transmit and receive channels (`esp32.io/rmt-tx`, `esp32.io/rmt-rx`) with pins and carrier from `kube32.io/rmt-tx` and `kube32.io/rmt-rx` annotations, `esp32_rmt_send` and the non-blocking `esp32_rmt_receive` with a per-channel frame queue, node capacity and scheduling, the Cardputer's IR LED as the default TX pin, Rust SDK bindings, and the `irremote` example that decodes and sends NEC codes.
- I2C device discovery: nodes label themselves `i2c.kube32.io/0x<address>: bus-<n>` for devices detected on their I2C pins so `nodeSelector` can place pods on nodes with matching hardware, and the `rfid` example reads ISO 14443-A tags through an MFRC522-compatible reader.
- Devices (`kube32.io/v1` `Device`, short name `dev`). A Device is a part wired to a node. A driver pod on that node operates the part. Apps on any node, including `kube32-sim` workers, reach it through a Service with the Device's name. The API server checks each Device against a driver catalog (`bme688`, `miniscale`, `rfid`, `chip-temp`, `button`, `switch`). Devices have a `status` subresource and Table output. The Device controller keeps the driver pods, Services and status. It replaces failed drivers with back-off. It creates Devices for the parts that discovery identifies (`kube32.io/discovered`), and sets them `Absent` when the part goes. `kube32-cli devices` lists Devices with the latest reading of each driver.
- Shared I2C buses. Device grants (`kube32.io/i2c-device`) give several pods one address each on one bus. The bus switches PCA9548A multiplexer channels before each transfer. A pod that claims the whole bus and device grants keep each other `Pending` (`BusInUse`). `esp32.io/gpio-input-<n>` claims a pin for reading only, also GPIO 0 (the boot button).
- I2C discovery behind PCA9548A multiplexers (M5Stack PaHub), with chip identification by register reads, `bus-<n>.mux-<hh>.<channel>` node labels, and the `kube32.io/i2c-devices` node annotation.
- `kube32-sim --sim-i2c` attaches simulated parts (PaHub, BME688, Unit Mini Scales, MFRC522) to the simulator's I2C bus, and `kube32-sim` nodes carry the label `kube32.io/simulator`.
- `kube32.io/tick-interval` configures a pod's `k32_tick` period.
- Device drivers (`apps/drivers`), one pod for each part. A driver serves its readings on `GET /`, its units and actions on `GET /describe`, and its actions on `POST /`. It publishes each reading on `device.<name>`. The firmware embeds these drivers as `wasm://embedded/driver-<name>`: `bme688` (Bosch BME688 and BME680: temperature, pressure, humidity, gas resistance), `miniscale` (M5Stack Unit Mini Scales: weight, tare, LED), `rfid` (MFRC522-compatible readers), `chip-temp`, `button` (debounced GPIO input) and `switch` (GPIO output).
- `esp32_chip_temp_read` reads the ESP32-S3's internal temperature sensor, granted by `hardware.kube32.io/chip-temp` (`CHIP_TEMP`). `k32_app_abi.h` declares the GPIO imports and their `K32_GPIO_*` modes.
- The `room-monitor` example combines a room's sensors, found by label through Services, into one JSON answer and page (`examples/devices/room-monitor.yaml`).
- Firmware rollouts through the cluster: an A/B partition table with bootloader rollback, `kube32-cli firmware push` staging an image on the control plane in resumable ranges (over Wi-Fi or the USB serial gateway), and `kube32.io/v1` `FirmwareRollout` updating workers one at a time and the control plane last. Each node downloads the image in small ranges, checks its SHA-256, reboots into it, and confirms it once healthy. An image that resets or fails to report Ready rolls back, and the rollout stops at the first failure. Nodes report their firmware version in `kubectl get nodes -o wide`, firmware annotations, a `FirmwareUpdate` condition, and Events.
- Each control plane generates a cluster access point password, and `K32_CMD:APPASS` configures it on workers.
- Python integration test suites (`tests/integration/runner.py`) for API, validation, resources, workloads, cluster, and federation in CI.

### Changed

- Allocatable `memory` and `esp32.io/psram` on a control plane leave out 192 KiB of PSRAM for the system (64 KiB on a worker with PSRAM), up from 128 KiB: the object store, the JSON of list and watch responses, the controllers' working sets, the console relay and firmware staging allocate there, and a node whose pods filled the rest ran out of memory in them. `K32_CMD:SYSRESERVE:<size>` sets another figure from the next boot on, `kube32-sim --system-reserved <size>` sets it for the modelled heap, and the Node reports it in the `kube32.io/system-reserved` annotation. `capacity` less `allocatable` covers it ([docs/hardware-spec.md](docs/hardware-spec.md#node-and-pod-memory-figures)).
- A list response that fails for memory before its headers are sent answers with a 503 Status. The stream no longer ends with a terminating chunk when the response is cut short by an exception, so a client sees a failed transfer instead of a list that looks complete.

- The firmware version drops the `v` of a release tag: a build of tag `v0.4.0` reports `0.4.0`.
- `K32_CMD:SCAN` scans on a control plane that runs only its cluster access point.
- `kube32-sim` trusts the CA bundle of the system it runs on (Debian, Ubuntu, Fedora, Alpine, openSUSE and macOS locations) for pods' `https://` calls, besides OpenSSL's default paths.

- The Deployment, DaemonSet and Job, and Device controllers and the scheduler run a pass when an object that they read changes, when a wait that they set ends, and every 30 s (the scheduler every 5 minutes) without a change, instead of every 1 to 3 s. Node heartbeats, Leases and Events cause no passes. The scheduler tries a pod that does not fit again after a change that can make it fit, with a back-off of 1 s doubled up to 10 s, and leaves the pod unchanged when the verdict is the same. A Deployment pass parses each pod once, and a scheduler attempt lists the pods once for all nodes.
- Pods use less of the pod pool on boards without PSRAM. Without `kube32.io/wasm-stack`, the wasm3 value stack sizes to what the module's call chains need, up to the 4 KiB or 16 KiB default. The shared interpreter stack lends the compiler its scratch space while a module loads. Function constants follow their code on its code pages, and code pages shrink to fit the pool block's free pieces. Metering skips zero-cost charges, and the loader drops function names from the name section.
- Memory admission estimates a pod's size from its module's sections and call chains using wasm3's ESP32-S3 structure sizes in both the simulator and the board. The `[POD]` load line reports the bytes a pod took from the pool block, the block's free bytes, and its largest free piece.
- Inline images are kept apart from the objects that carry them. A Pod, Deployment, DaemonSet or Job written with `kube32.io/wasm-base64` is stored with `kube32.io/wasm-sha256` and `kube32.io/wasm-size` in its place. The API server decodes the module as the request body arrives and stores it in the object store under its SHA-256, on flash when the store has a journal. Kubelets read it from `GET /apis/kube32.io/v1/images/<sha256>` and check it against the digest. An image is deleted with the last object that refers to it, and objects stored with their module inline give it up when the control plane starts. `kubectl apply` keeps `sha256:<digest>` in place of the module in `last-applied-configuration`.
- The watch replay ring for `resourceVersion` watches holds at most 64 KiB of objects next to its 32 events, and each event is written to every stream from one copy.
- Allocatable `memory` and `esp32.io/psram` are fixed at what pods can be given with no pod running, and the scheduler subtracts the requests and Pod Overhead of every bound pod that has not terminated, as kube-scheduler does. A pod without a memory request counts as the 64 KiB page the kubelet gives it. What is free now is in the Node's `kube32.io/memory-free`, `kube32.io/heap-free` and `kube32.io/psram-free` annotations. The kubelet rejects a pod whose linear memory cannot be placed in one piece.
- wasm3 keeps an f32 value single precision in its float register, so f32 operations make no soft-float calls on the ESP32-S3, whose FPU is single precision. Wasm loads and stores copy their operands inline, and the firmware builds without `-mfix-esp32-psram-cache-issue`, an ESP32 workaround that put a memory barrier in every interpreter operation. The image is 18 KB smaller.
- A message queued for a busy pod takes one allocation. Boards without PSRAM queue at most 8 such messages (16 elsewhere) and drop the oldest first.

### Fixed

- A Wi-Fi station without PSRAM, such as the Cardputer, stays on its access point while sockets read slowly. A received frame stayed in the driver's receive buffer until a socket read it, and once frames held every buffer the station could not receive the access point's key handshake. The station copies each frame out and returns the buffer at once.
- A worker that receives the control plane's UDP HELLOs keeps its Wi-Fi link while the API server is slow or restarting, instead of joining the access point again, restarting Wi-Fi or rebooting.
- A control plane whose PSRAM is fragmented keeps answering API requests. Each request took a 16 KiB scratch block from the heap, so once the free PSRAM lay in smaller pieces every request answered `503 node is out of memory`, also with over 100 KiB free. Each API worker now allocates a 1 KiB scratch at start, and a request whose objects are under 4 KiB needs no larger block. A control plane also sets 64 KiB of PSRAM aside at boot for allocations over 4 KiB (lists, copies of large objects, controller working sets), which go there first and to the heap when it has no room ([docs/hardware-spec.md](docs/hardware-spec.md#node-and-pod-memory-figures)). The `[MEM]` console lines report the largest free PSRAM block and the region's figures, and the first allocation of 1 KiB or more refused between two lines prints its size, the PSRAM figures and a backtrace. The IPC dispatcher's stack on a board with PSRAM is 8 KiB, down from 32 KiB: it queues messages and runs no pod code.
- A Deployment creates and scales its pods on a control plane with little free PSRAM. Each pod it created recorded two events, and each event record copied all 64 stored events twice (about 50 KB a copy) while the pass also held a copy of every Deployment and every pod and the scheduler a parsed copy of every node, so a pass needed about 120 KB more than the control plane at rest and failed with `std::bad_alloc` on a busy devkit. The controllers, the scheduler, the event recorder and the API's lists now read the store in place (`Store::visit`): they keep the fields they use, copy only the objects they act on, and read Deployments one at a time. With 10 Deployments, 6 pods, 3 nodes and 64 events, a pass that creates a pod peaks at 67 KB of heap instead of 209 KB. The API filters a list by its field and label selectors before it copies an object, and streams lists of Events, Services and the other generic kinds instead of building the body in one block.
- A pod log read (`kubectl logs`) that waits more than 5 s for the node's storage no longer corrupts another task's stack. The read returned while its request stayed queued, and the storage task later wrote the result into the returned call's stack frame.
- The object store journal keeps writing on a control plane whose PSRAM is fragmented. Reclaiming a sector read each live record into one allocation of its size; when that allocation failed, the journal stayed in reclamation, appended without its reserve until every sector was in use, and refused every write from then on, also after a restart, with `flash journal refused <key>`. Records now move in 128-byte pieces, journal writes read values from the store instead of copying them, and a journal with no free sector for the live records of its oldest one moves them through RAM. A refused write reports its cause: `503 ServiceUnavailable` when the node is out of memory, a full journal, no sector to free, or a flash error. `K32_CMD:STORE` counts refusals by cause.

- A catch in the housekeeping loop and in the storage task is reached. On Xtensa the unwinder stops at a frame whose return address is zero, which is how FreeRTOS starts a task, so an exception thrown under a task's entry function was never caught there and the node aborted; the control plane did so when its PSRAM ran out. Every task body now runs one frame below the task's entry, and a task's exception globals are set up when it starts, so its first throw allocates nothing. `K32_CMD:THROW` raises `std::bad_alloc` in the housekeeping loop to check this on a board.

- Out of memory in a long-running task ends the pass, not the task. The housekeeping loop of the firmware (ingress, firmware rollouts, peer seeding, journal flush, Wi-Fi supervision), the pod tick thread, the pod event thread, the SSE hub, the IPC receive thread and the pod log writer catch `std::bad_alloc`, log it and run again on their next pass. A control plane whose pods had filled PSRAM aborted in the housekeeping loop and rebooted.

- A kubelet's log epoch fits in 53 bits, so the control plane reads it exactly from JSON and keeps the logs of a node's next boot instead of dropping them as repeats. A JSON number outside `int64_t`, such as an older node's epoch, clamps to that range instead of converting with undefined behavior.
- A call to a host function the node does not provide, such as one from a newer SDK, traps every time. The first trap left the calling site in the guest's code pointing at no code, so the next call into the same export (`k32_tick`, `k32_handle`, `k32_event`) took the whole node down, `kube32-sim` with SIGBUS.
- A pod whose module comes from the API server's image store, the card or an annotation starts on a board without PSRAM whose general heap has no free piece the module's size. The kubelet reads the module into pod memory, placed as the pod's other allocations are (the pool block first), and the container charges it to the pod. Memory admission and Pod Overhead count the module's bytes for such images, so a pod's scheduled memory grows by its module's size; embedded images are mapped from flash and count nothing. A module that finds no room makes the pod wait with `InsufficientMemory` instead of failing with `ErrImagePull`.
- A node with PSRAM advertises the PSRAM that pods can be given as its allocatable `memory`, not its free internal heap, so pods that request more than a few KiB, such as `examples/echo.yaml`, schedule on the control plane.
- `kubectl top pod` reports every byte a pod holds, under `memory` on every board: wasm3's structures, compiled code, value stack, linear memory, the module's copy and its thread's stack. It reported linear memory and value stack only, and on a board with PSRAM reported `memory` as 0. `kubectl top node` reports internal RAM and PSRAM in use, on the base of `capacity` `memory`, instead of internal RAM only (the host's RAM in use in the simulator, not the process's resident set). `kubectl top pod` lists every running pod, not 32 at most.
- `MemoryPressure` compares free internal RAM with its threshold. On a board without PSRAM it counted the pod pool block's free part as free heap.
- `GET /api/cluster` reports free internal RAM as `free_heap` and free PSRAM as `free_psram`, and what pods can be given now as `free_pod_memory`. `free_heap` was allocatable memory and `free_psram` the linear memory the pool block could take whole.
- A pod's linear memory that grows in place at the start of the pool block counts at its new size, so the block's small heap no longer starts inside it.
- `K32_STATUS pods=` counts the runtime's containers, not only request-handling pods. Console lines print KiB as `KiB`.
- Inline images of 10 KB and more fail no more on a control plane with 2 MB of PSRAM. Every list, watch event, controller pass and kubelet sync copied a pod together with its module. For a 10 KB module one create took up to 225 KB of heap, a status update 139 KB and a controller pass 129 KB, and the watch replay ring kept 99 KB, so creates, status updates and deletes failed with `503 node is out of memory`. A create now takes about 50 KB whatever the module's size, and modules up to the journal's capacity deploy.
- A request that runs out of memory leaves nothing half done. A store write or delete happens with its journal write and its watch event, or not at all. A journal write that runs out of memory no longer blocks every later write until a restart. A watch event that cannot be queued makes its streams answer `410 Expired`, so their clients list again. The HTTP server's threads answer `503` and keep serving instead of ending the process.
- Concurrent updates of one object keep every change. A Pod or Node `PATCH`, or `kubectl delete` while the kubelet reports status, retries on the newer object when another write came first, so a status update no longer drops `deletionTimestamp` and a heartbeat no longer drops an annotation patch.

- `test_driver_frames` counts operation frames with the boards' dispatch. On an ARM64 host, wasm3 preloaded the next operation and dispatched it outside the counter, so the test reported fewer frames than a call uses on an ESP32-S3.
- Endpoints, EndpointSlices, Ingress routes, Service calls and service links reach a pod at its node's pod port (`status.daemonEndpoints.kubeletEndpoint.Port`), not at its `containerPort`. Thus the boards can reach pods on a `kube32-sim` worker that runs with its own `--pod-port`. NetworkPolicy ports still match the pod's own port.
- A node keeps its cordon when it registers again after a reboot or after rejected heartbeats. The registration does not set `spec.unschedulable`.
- A container's environment is kept once per pod instead of twice.
- `esp32_get_time_us` returns the node's uptime in microseconds. It returned milliseconds multiplied by 1000.
- The BME688 driver keeps its compensation steps out of line, so its first reading fits the native stack of a board without PSRAM.
- A request that fails with `503 node is out of memory` logs the error behind it.
- A native stack overflow trap reports how much stack the call had when it began and how much it had used.
- Stop the ESP-IDF I2C master driver from logging every failed transfer on a pod's I2C bus. The HAL reports the first three failures and every 100th.
- Modules that run out of memory while wasm3 grows its function, global, tag, memory, or table arrays now fail to load instead of crashing the node.
- Pods leave a PSRAM reserve for the system (128 KiB on a control plane, 64 KiB on a worker with PSRAM). Without this reserve, pod code and structures can drop free PSRAM to 16 KiB, causing API requests to fail with 503 and firmware staging to run the control plane out of memory.
- The USB console survives software resets: on any non-power-on reset, the board disconnects from the USB bus for 100 ms so the host enumerates the port again, and it flushes any partial line from the early console before its driver starts. Previously, a reboot could leave the port silent until the board is unplugged.
- Fix loading inline and SD card images placed in PSRAM: the ESP32-S3 maps flash and PSRAM into a single address range, which caused the loader to treat the pod's PSRAM copy as flash and free it.
- Include object metadata labels in Table rows so `kubectl get --show-labels` and `-L` display them.
- Clear the I2C bus after a failed transfer.
